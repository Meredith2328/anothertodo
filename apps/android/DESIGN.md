# Android 页面与操作设计

视觉参考：[十派的玩具箱](https://meredith2328.github.io/)。界面使用黑白灰、直角边框、阶梯形图标和阅读字体。正文保持 16px，说明与任务属性保持 13–14px。绿色主要用于保存反馈与完成方块，红色用于逾期、阻塞和保存失败。任务列表使用分隔线，设置使用清晰分区。

日程交互参考 [TickTick 的日历功能](https://ticktick.com/home)，使用不同时间尺度安排任务；四象限根据本项目实际的优先级和截止日期分类。

## 任务页

1. 用户查看当前待办、定位任务，并完成高频操作。
2. 页头显示页面名称与当天日期，右侧提供撤销和选择。任务列表与依赖地图在正文顶部切换。搜索位于列表上方；待办、今天、接下来、等待、已完成按处理范围切换。正文按日期分组，标题优先，时间、优先级、项目和依赖状态位于标题下面。右下角加号是新增入口。
3. 任务详情通过点击标题出现；批量操作栏在开启选择模式后出现；未来等待任务通过“查看等待任务”入口访问。
4. 点击方框完成任务，点击标题进入详情。依赖未完成时明确显示阻塞原因。批量操作完成后可以整次撤销。
5. 长标题自然换行，任务属性允许换行，正文纵向滚动。选择范围限定当前实际展示的结果，页底保留导航和操作空间。

空内容显示当前没有任务的状态与添加入口。搜索错误显示具体原因；成功操作显示短暂反馈。

## 依赖关卡地图

1. 用户查看一条任务路线已经完成到哪里，找到当前可以执行的分支，理解接下来需要完成的前置任务。
2. 顶部选择依赖路线，显示真实完成数量、进度条和状态图例。地图在深灰底色上使用铜色道路、菱形关卡与像素细节，从下方起点向上展开。完成节点使用绿色，可以执行的节点使用金色，等待节点使用灰色。所有可以执行的分支同时标记；选中节点带边框，其前后道路加重显示。地图下面展示选中任务的完整标题、状态与主要操作。
3. 独立任务通过“显示独立任务”开关加入路线选择。前置任务和后续任务在选中详情中展示，点击可以定位到对应节点。完整编辑通过“查看任务”进入；已归档的记录提供恢复入口。缩放、全貌、定位选中和定位可执行分别对应明确的浏览目的。全貌包含完整路线，较小比例下隐藏节点文字，并用固定大小的金色标记保留可执行位置；定位后恢复可阅读比例。
4. 通过任务页切换、更多页面或任务详情中的“查看依赖地图”进入。首次进入定位到可以执行的节点，并将地图带入页面可见区域；完成任务后定位到下一处可以执行的分支。汇合节点等待全部前置任务完成。详情修改自动保存，关闭后保留选择与浏览位置。系统返回键先返回任务列表。
5. 每条连通路线独立展示，避免无关任务混在同一地图中。手机使用地图与详情的纵向顺序，地图可以双向滚动、触摸拖动和按钮缩放；宽屏使用地图与详情的左右布局。横屏根据可用高度安排地图，点击节点后定位到详情与任务操作。地图节点显示最多三行名称，点击后在详情中阅读完整标题。长依赖链保留全部节点，布局在独立 Web Worker 中计算；返回列表时终止未完成计算。

空内容展示添加依赖的入口说明；加载显示绘制状态；绘制失败显示具体原因与重新加载入口。未来等待日期、取消、自定义状态和缺失依赖记录均保留明确说明。全部完成的路线显示完成反馈，当前无法执行的路线引导查看等待节点。

关卡视觉参考森林冰火人的分支道路与菱形关卡选择形式，使用 CSS 和 SVG 绘制地图元素。任务数据直接来自原有依赖记录，包含归档中的前置任务；缺失记录以提示节点表示。

## 批量输入页

1. 用户逐行录入一批任务。
2. 顶部显示“添加任务”，输入区域占据主要空间，明确标注“一行一个任务”。输入下面显示任务数量，主要按钮为“检查任务”。
3. 日期、项目、标签、重复与依赖通过原有输入语法填写；从日程页进入时，选中日期用于缺省截止日期。
4. 用户填写多行后进入检查页；关闭可以返回原页面。空输入会指出需要至少一条任务。
5. 输入区域支持长文本和自然滚动，软件键盘出现后窗口重新安排高度，检查按钮保持可访问。

使用检查步骤的原因：同一批任务可以互相依赖，用户需要在实际写入前确认每一行的解析结果和执行顺序。

## 批量检查与依赖确认页

1. 用户确认每一行的标题、日期和任务依赖，然后统一添加。
2. 任务按照输入顺序编号展示，标题获得最高视觉优先级，日期、优先级和备注就近显示。每条识别出的关系显示“需要先完成”或“先于”，候选按任务名称、编号和状态展示，选中结果使用直角边框及选中说明。
3. 只有包含关系语法的行展示候选。没有匹配、多个候选和循环依赖会出现具体反馈；保存按钮等待所有依赖得到明确结果。
4. 用户点击候选确认，使用“返回修改”调整原始输入，使用“添加 N 个任务”完成一次事务。出现失败时整批保持可修改，任务数据保持原有状态。
5. 每条任务独立占据自然高度，候选允许纵向滚动。使用真实长标题和多条输入检查了文本换行与主要操作。

## 任务详情与自动保存

1. 用户修改具体任务的内容、日期和执行顺序。
2. 顶部显示任务详情与关闭按钮，紧邻显示保存状态。默认展示标题、截止时间、优先级和备注；主要状态操作为完成任务或重新打开。
3. 项目与标签、重复与等待、执行顺序、提醒和其他操作使用独立展开区域。执行顺序区域展示父任务和依赖任务，并通过“查找依赖任务”选择新的前置任务。删除、取消、推迟提醒等操作在需要时展开。
   标题中输入执行顺序语法时，识别出的候选在标题附近展示；选择后同步更新依赖。执行顺序区域同时提供后续任务入口。
4. 修改后自动保存，快速连续修改合并为一次编辑的撤销记录。关闭、返回和执行其他任务操作前等待保存完成。失败时显示具体原因，用户可以修正字段，或明确放弃未保存内容返回。已经保存的内容保留。
5. 长标题和多行备注使用可增长的文本区域，详情页纵向滚动。手机使用全屏详情，宽屏使用右侧独立详情区域。

展开字段的原因：备注与日期属于高频编辑；重复、父子关系、投递方式和状态迁移拥有各自的上下文，按需出现可以减少同时展示的控件。

## 日程页与日历视图

1. 用户安排具体日期的任务。
2. 顶部依次提供日历、周历、月历、重要度、四象限切换。日历视图显示选中日期、前后切换与返回今天，正文按实际截止时间列出当天任务。
3. 没有日期的任务在独立区域展开，依赖状态直接出现在任务属性中。
4. 切换日期后可以通过加号为该日期添加任务；点击已有任务编辑。底部导航允许返回任务页。
5. 当天任务按时间排序并自然滚动。空日期保留添加引导，正文保持完整阅读宽度。

## 周历视图

1. 用户比较一周内各天的安排并找到可用日期。
2. 顶部显示整周日期范围与七天选择条，每天显示真实任务数量。正文使用七个日期列，任务按时间显示，当前日期列自动进入可见范围。
3. 没有日期的任务通过底部展开区域查看。
4. 日期选择条定位当天，前后切换移动一周，新增任务采用选中的日期。
5. 每列保留 210px 阅读宽度，手机允许横向浏览日期列，长标题自然换行；日期列内的内容允许纵向滚动。

## 月历视图

1. 用户查看整月分布并选择安排任务的日期。
2. 顶部显示月份与前后切换，日期区域以星期一作为一周起点。当天加重显示，选中的日期反白显示，日期格显示真实待办数量；选中日期的任务位于网格下方。
3. 详细标题与时间在日期任务列表中展示，日期格保留日期和数量，避免塞入长标题。
4. 点击日期查看任务；月份切换保留尽可能接近的日号，月底移动到较短月份时使用有效日期；新增任务继承选中日期。
5. 日期格保持七列和可点击区域，任务列表自然滚动，较小窗口保持原有字体和间距。

## 重要度视图

1. 用户根据本项目的优先级决定处理顺序。
2. 按配置中的优先级从高到低排列，未设置优先级的任务置于末尾。每组标题显示名称与数量，任务保留截止日期和依赖标记。
3. 修改优先级通过任务详情完成；自定义档位在设置的完整配置中管理。
4. 用户打开任务调整档位，自动保存后分组立即更新。
5. 分组纵向展开，长任务标题获得完整空间，组内任务数量增加时自然滚动。

## 四象限视图

1. 用户区分当前应优先处理和可以安排到后面的任务。
2. 页面明确显示分类依据：最高优先级为重要，今天到期或已经逾期为紧急。四组依次为重要且紧急、重要不紧急、不重要但紧急、不重要不紧急，每组显示真实数量。
3. 任务详情负责修改优先级与日期，依赖未完成的任务保留阻塞标记。
4. 修改任务后象限立即更新。用户可以切换到具体日历安排日期。
5. 手机顶部保留两列两行的象限概览，点击象限后在下方展示完整任务，宽屏直接展示两列任务区域。任务区域高度由实际内容决定，长文本自然换行。

## 统计页与完成方块

1. 用户查看当前进度与长期完成记录。
2. 未完成、逾期、今天与本周到期、近期完成、待发提醒和重复任务优先展示，数量使用清晰字重与留白。
3. 完整状态计数、备注、子任务和投递失败等信息通过详细统计展开。完成记录拥有独立开关，用户开启后显示绿色方块和时间范围选择。
4. 开关与范围写入本机持久化设置。方块根据任务真实完成时间统计，包含归档中的记录。点击方块显示日期与完成数量，可选择最近三个月或全年。
5. 手机显示两列主要指标，宽屏显示四列。完成方块保留固定尺寸，全年区域横向滚动。零完成日期显示灰色；未来日期保持不可选。

## 更多页

1. 用户进入低频管理功能。
2. 全部任务、项目、标签、归档、同步、导入、导出、设置与帮助使用分隔线列表，名称优先，简短用途位于名称下面。
3. 对应管理内容通过各自独立页面出现，主列表保留清楚的返回方向。
4. 点击入口进入操作，关闭后返回更多页，底部导航返回任务或日程。
5. 名称和说明允许换行，入口保持足够触摸高度，内容多时自然滚动。

## 同步、导入导出、设置与归档

1. 每个管理页面只处理对应操作。
2. 同步按仓库、分支、认证与作者信息排列，主要操作为立即同步；导入按选择文件、检查内容与导入排列；导出按格式、范围与保存排列；归档按天数与历史记录排列。
3. 设置中的提醒权限、排序与语言优先出现，完整 TOML 与自定义通知方式属于高级配置。任务数据导出与 Git 认证分别管理。
4. 处理中明确显示状态，成功后显示结果，失败后保留输入与原因。同步和导入均使用依赖校验，依赖循环会阻止应用数据写入。
5. 页面使用纵向阅读顺序和自然滚动，配置文本保持可读字号，长仓库地址与任务名称允许换行。
